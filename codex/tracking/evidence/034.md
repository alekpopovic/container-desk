## Acceptance criteria

- Dangling/multi-tag images: real private Engine has two zero-layer fixture images; one has two tags and two metadata-only container references, the other is genuinely untagged. App IDs, tags, bytes, Docker dangling filter and exact references match independent native CLI results. These fixtures do not prove workload execution or nonzero-layer disk accounting.
- Identical tags on different hosts: parser and browser/IPC tests use separate scopes/identities and prove a late old-host response cannot replace the newly selected image. Native direct/jump aliases refer to the same isolated Engine; they are not claimed as two distinct daemons.
- Masking: Rust tests omit synthetic environment/command values and mask all label values; native IPC assertions and release UI show names plus “Masked”, never the synthetic secret values. Known app activity/preferences files are checked for the synthetic image marker. No image metadata is persisted by the feature.
- Scope/bounds: existing read scheduler/admission, total deadlines, pinned daemon checks, 5,000 identities/references, 64-ID inspect batches and byte/text/page caps are reused or explicitly defined. Hostile IDs and ancestor false positives are tested. No image mutation API is exposed.
- One initial browser run observed a blank fixture page before initialization; an explicit bounded initialization wait and runtime-error capture were added, then all 18 cases passed. Native automation initially acknowledged the container-reference element click without any DOM click event; instrumentation confirmed no delivery. It now waits for paint and retries only an undelivered read-navigation click (maximum three), requiring a trusted DOM click. No mutation or terminal input retry was added. Final native run passed both aliases.

## Remaining limits

- Native proof is Linux x86_64, Ubuntu 26.04.1/X11 only. No macOS, Wayland, Ubuntu 24.04 baseline, packaged installation, signing or notarization evidence.
- Fixture images have zero layers; real repository-digest preservation and descendant-reference rejection are parser tests here, while real multi-tag/dangling/exact container references are native checks.
- Refresh is explicit; image events are not subscribed. Missing/changing reference candidates fail the read rather than silently report a complete snapshot. No image export/reveal/pull/delete/prune feature was added.
