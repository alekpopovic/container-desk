## Acceptance criteria

- Missing Docker: actual SSH command to an absent remote executable → DockerMissing.
- Stopped/unavailable daemon: real remote CLI to absent lab Unix socket → DaemonUnavailable. No actual Engine was stopped.
- Permission denied: real CLI as non-root SSH user against root-owned 0600 synthetic listener → PermissionDenied.
- Rootless context: real CLI with default DOCKER_HOST and explicit named rootless context reaches the synthetic API, decodes reported rootless/Linux/version/daemon ID, and uses the correct endpoint despite a conflicting stopped-socket environment override. This verifies selection/parsing, not a running rootless Engine.
- Compose absent: real CLI without plugin → Absent while Docker readiness remains available. Positive Compose JSON version is covered by a deterministic response fixture, not an installed plugin in this lab.
- sudo password: real remote sudo -n under existing fixture policy → SudoAuthenticationRequired with no password/askpass input. No permissions or sudo policy are edited by the app; only the disposable image provisions test policy.
- Additional native cases: nonexistent named context, non-Linux synthetic daemon, excessive output and hanging command → bounded specific failures. A complete native ProxyJump session reaches Ready using the explicitly synthetic Docker API and shutdown releases its gate.
- Consistency: every current read/inspect/log/image, mutation and terminal preparation uses the same named context and fixed privilege prefix; default endpoint pins --host; drift/changed daemon is rejected. Same alias with changed Docker options gets a new generation; old snapshots cannot attach. Browser checks show actual endpoint/daemon/Compose status and lock target controls until disconnect.
- Lab cleanup removed exact owned containers/network/agent/temporary identities; SSH config/trust hashes unchanged; no askpass marker. No user/production daemon socket is mounted into the lab and no production alias is selected.
