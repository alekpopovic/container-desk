## Changes and decisions

- Added optional startup-only `resource-limits.json` in app data, a narrow read-only IPC command/capability/generated contract, validated immutable renderer copy, and visible effective limits/fallback notice. Defaults remain 20,000 lines/8 MiB per log buffer, 360 stats points (12 histories), four jobs. Configurations may reduce these to 1,000 lines/256 KiB, 60 points and two jobs. Unknown fields, invalid numbers, special/symlink files and files over 4096 bytes are rejected without blocking on a FIFO.
- Active live sessions are configurable from zero to the implemented maximum of one. Both native session-entry paths enforce this in Rust; demo remains available. The architecture's proposed three-host target was not implemented concurrency. This increment preserves the working single-selected-host session model.
- Applied bounds to Rust retained snapshot/stream queues, frontend log retention, stats history and native/backend job pools. Fixed shutdown's former hard-coded four-permit wait to use the runner's actual capacity; a reduced-capacity ownership/reaping regression passes.
- Actual synthetic event pressure exposed repeated inspect remounts on every inventory timestamp. These reset the selected tab and refetched a roughly 1 MiB response. The same identity now retains its inspect tab and masked snapshot, marks details as older when inventory advances, and offers an explicit refresh. Revealed values are masked and pending reveal responses fenced on inventory refresh; full identity changes still discard the component. Native pressure records the actual inspect-read count.
- Added reproducible Node retention, native Rust parser/queue and release-app pressure harnesses. Kept existing measured virtualization (24 container rows, 32 log rows), bounded ACK batches and event coalescing; no speculative new rendering layer.
- [Resource configuration/methodology](../../../docs/resource-limits.md) documents limits, scope and exact reproduction commands.

## Measured results

- Node retained heap stabilized near 15.2 MiB after the first full 20,000-line buffer; total measured run 928.8 ms. This deliberately invokes GC and is not whole-app memory evidence.
- Rust log queue: 200,000 records, peak 8,388,608 bytes/16,247 lines for this record size, 183,806 discarded and maximum observed batch 128; 113.2 ms.
- Rust event queue: 200,000 unique hints, peak 512 events, 1024 dedupe keys, 199,488 discarded, batch 64; 301.0 ms.
- Rust parsers: 100 iterations each; 1,019,912-byte masked inspect input in 612.5 ms total, 1,000-summary/141,889-byte listing in 610.9 ms total. These are unoptimized in-process synthetic timings.
- Native final run: 1,000 summaries render 24 rows initially; 8,000 log lines/440,000 displayed bytes retained with at most 32 log DOM rows. Large inspect input 1,029,985 bytes, 1,518.1 ms native roundtrip, exactly **one** inspect read despite sustained events; Environment remains selected across refreshes.
- Native filtering (including deliberately paced real keyboard input and driver roundtrips): 518.9/561.3/537.6 ms before sustained pressure, **607.8 ms** under pressure. Frame intervals: median 16 ms, p95 32 ms, p99 45 ms, maximum 182 ms.
- Whole-app/descendant/leased-master RSS: baseline 656.2 MiB, peak **866.3 MiB**, final 30-second range 851.3–866.3 MiB; median growth versus seconds 30–60 **11.20 MiB**, within the predeclared 32 MiB gate. PSS was available except for at most one short-lived process during a sample; all raw values remain in the report. Memory did not return to startup size after disconnect (856.5 MiB RSS, about 603.2 MiB PSS), consistent with retained allocator/graphics memory; no zero-growth or return-to-baseline memory claim is made.
- Owned SSH count: baseline zero, observed maximum **six**, after cancellation zero; **33 distinct PID/start-time identities**, including leased background masters, were gone, with zero zombies. The follow-up actual stream checkpoint passed with a 78,675-record pressure drop marker and maximum IPC batch 128.

## Acceptance and limitations

The native workload uses 1,000 synthetic summaries and 1024 synthetic environment/label entries over real SSH; it does not claim 1,000 actual Docker containers. The high-rate event source is also synthetic. Logs come from an actual isolated owned Docker container. Source loops target roughly 50,000 log lines/s and 5,000 events/s; those rates describe the generators, not measured IPC throughput. Real memory/latency/process measurements are from the release app, including its WebKit processes and background masters identified by the app's leased runtime paths.

Configuration in the native run is 8,000 lines/1 MiB, 60 stats points, one host and four jobs. Lower stats retention is separately exercised with 1,000 appended points. Queue loss remains visible and no stream retries a mutation or terminal input. Cancellation checks both baseline process counts and PID/start-time identities, including background ControlPersist masters. The subsequent existing native stream checkpoint verifies 128-record ACK batching, visible pressure drops, cancellation/reaping and server loss under load with unchanged strict trust.

Earlier attempts were not counted: the first WebDriver connection closed during inspect navigation; a later zero-delay WebDriver clear left old characters in a controlled search field, so the final harness uses paced real Ctrl+A/Backspace/text keys. Actual event pressure separately exposed the inspect remount/tab-reset issue described above; the final native run verifies that Environment remains selected across repeated snapshots and records one large read. A previously stale preferences test expected an old error sentence; it now checks the current actionable storage guidance. Compilation initially exposed test-only TS derive/import assumptions and an unused legacy constant; all final checks pass.

RSS sums include shared pages more than once and allocator/graphics memory may remain after disconnect. The plateau gate is explicit (last 30 seconds versus seconds 30–60 median growth at most 32 MiB); raw samples are retained rather than interpreting fixed buffer capacity as measured application memory. This finite Linux run does not prove indefinite stability, macOS/Wayland performance, low-memory hardware behavior, installed packages or signing readiness.
