## Changes and decisions

- Retained the existing Python W3C WebDriver harness using official tauri-driver/WebKitWebDriver. Current [Tauri documentation](https://v2.tauri.app/develop/tests/webdriver/) explicitly supports that path for custom/non-Node clients. No replacement framework or extra dependency was needed.
- Added nondefault Cargo `native-automation` feature. Ordinary executable startup removes five Tauri/WebKit automation/inspector environment variables before Tauri/GTK/Tokio start. The unsafe environment mutation is limited to the single-threaded executable entry point. Pinned upstream Tauri runtime source otherwise enables WebKit automation from an environment variable even with release optimization.
- Build helper creates a separate ignored automation artifact, removes the intermediate instrumented shipping-path binary, then builds ordinary production last. Existing native helpers select the explicit test artifact. No test plugin, server, mock-control IPC, global Tauri API or permission was added to production or to the current instrumented build.
- Added production-refusal harness and repeatable desktop orchestrator. Reused actual host/error, integrated log/terminal and IPC/security journeys. Updated development/security guidance and added `docs/native-testing.md`.
- Evaluated documented macOS embedded WebDriver (`@wdio/tauri-service` plus optional `tauri-plugin-wdio-webdriver`). It is suitable for native macOS automation with an audited, explicitly gated test build; not installed/executed here. Standalone official tauri-driver does not support WKWebView. No paid driver/key added. References and future feature/capability requirements are documented.
