## Acceptance criteria

- Named/anonymous volumes and mount relationships: real isolated Engine created one named volume shared by two metadata-only containers (RO and RW), a genuinely anonymous `/cache` volume, and an unused volume with driver options. Both SSH routes matched independent Docker CLI names, paths and exact container IDs. The app does not guess anonymous status from name shape.
- External drivers/no mountpoint: Rust parser and browser fixtures preserve external driver/global scope and render missing mountpoint as not reported. No real external plugin was installed; these are fixture checks.
- Deleted during refresh: the fixture-only read gate removes only the exact labelled disposable race container after candidates are listed and before Docker inspect. Native backend retained both surviving references, marked the result incomplete with the removed ID, then reconciled on another read. Browser test confirms incomplete is never rendered as no references.
- No remote data reads: app plans admit only fixed Docker metadata/probe commands. The owned gate's argv trace contains no filesystem command or returned `_data` path. The lab controller reads its own command-trace file separately; this is not an app filesystem operation. No volume contents were copied or browsed.
- Host identity, bounded parsing, hostile names, masking, stale read fencing and disabled stale reference links have targeted tests. Native frontend used real IPC and the actual Docker CLI; known preferences/activity files did not contain the synthetic volume marker. Snapshot text explicitly avoids deletion-safety claims.
- Native screenshots visually inspected; named metadata, masked label, actual two mount references and full IDs fit the inherited read layout.
