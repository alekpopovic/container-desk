- Extracted resolver process handling into the shared runner while preserving native config semantics and stricter diagnostic limits. Added generated operation_cancelled error mapping.
- Added structured destination argv defaults for connection timeout/keepalives/no PTY/noninteractive mode/strict host trust and suppression of unintended forwarding, key updates, inherited control sockets, local command/background/remote-command overrides.
- Added static synthetic child fixture and focused process tests; updated runner/resolution/status docs. No new dependency, generic execution IPC, terminal input API or remote dispatcher.

## Remaining limits

- No actual remote command, SSH authentication or Docker connection yet. The structured argv base must receive a centrally validated/quoted command from prompt 012 and be dispatched only by a scoped authorized owner.
- Destination options alone do not establish ProxyJump subprocess trust/authentication behavior; later native lab checks remain mandatory. App-owned control sockets and host-session ownership are future increments.
- The resolver keeps its backend diagnostic permit through bounded completion after caller loss. General Job cancellation is available internally; no UI cancellation button was added.
- Cancellation after future mutation dispatch cannot establish rollback and must never trigger replay. Trusted configuration may create detached processes/external effects beyond ordinary process-group cleanup.
- Filesystem/spawn/kernel cleanup stalls are not simulated here; guarantees are native tested behavior for local executables, with slots retained during cleanup. macOS remains unverified; no native window run or package/signing claim in this increment.
- Existing bundle identifier/generator notices and GitHub dependency alert remain open.
