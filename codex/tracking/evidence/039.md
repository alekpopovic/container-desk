Fixed quoted Docker exec with non-root UID/GID 1000, full container ID and selected sh/bash only. Structured operations retain their existing pipe/no-PTY path.
- Terminal-specific host permission requires existing management opt-in. Exact single-use confirmation, current scope and running-container/daemon preflight before opening. Narrow scoped read/input/resize/close IPC and generated contracts; readonly direct IPC remains denied in Rust.
- Bounded owner thread, queues and output reads, exact input sequence, nonblocking partial writes without replay, coalesced resize, consumer/idle limits, output-pressure closure, permission/session cancellation, process-group cleanup and child reaping. Debug payload masking; no transcript persistence/activity record.

## Acceptance and observations

- Echo checks distinguish actual generated output from input echo. Ctrl-C cancels a real 30-second sleep and allows the next command within three seconds. Remote stty reports the requested size; exit 7 is preserved.
- Shell-less fixture remains running with no /bin/sh; opening returns `terminal_shell_unavailable` without fallback. Both container primary processes remain alive after terminal signals. Only the expressly selected exec processes are affected.
- Read-only rejects terminal enablement and preparation; ordinary management also rejects preparation. Separate terminal opt-in is required. Reusing an opening intent or input sequence fails. Revocation immediately rejects input and closes the owner; exact old scope can still close after disconnect.
- A JSON inventory read succeeds while the terminal is active; the terminal-enabled SSH gate explicitly rejects a PTY for every structured Docker operation. Existing builder tests reject sending terminal plans through structured SSH argument construction.
- The first native run failed because the lab key retained OpenSSH's `restrict` no-PTY default despite PermitTTY yes. The fixture now uses `restrict,pty` only in terminal mode. No user key/config was changed; subsequent direct and jump native runs passed.
- No generic local shell runner, remote agent, Docker TCP port, key copying, terminal replay or transcript telemetry was added. The lab's separate local-PTY unit shell commands are test fixtures, not renderer-callable application code.

## Remaining limits

- Linux backend PTY execution and production build only; terminal UI is 040. macOS, Wayland, native package installs and signing/notarization are not proven.
- Fixed UID/GID 1000 may lack permissions or a suitable image working directory. No root override or user chooser in 039. Shell startup can fail even after running-container preflight; there is no fallback script.
- Already written terminal input may have performed changes. Closing cannot undo it or terminate independently detached remote work. Consumer must treat a lost input response as unknown and close, not retry.
- Default bubblewrap execution is broken; commands ran through the reviewed authorized execution path.
