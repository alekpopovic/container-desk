## Acceptance and observations

- Lifecycle and Compose actions target only explicitly created lab resources through gates restricting full owned IDs/configuration. No production alias, guessed host or user SSH/Docker config was used. Strict trust files remain unchanged; owned resources are cleaned in `finally`.
- Read-only is enforced in Rust at all remote mutation entrypoints. `set_management` requires selected current scope; prepared intents are cleared on revoke. Terminal remains unavailable with no main-window capability at 038; ordinary management does not grant terminal permission.
- Batch partial failure combines actual success/deletion with a deliberately gate-injected permission refusal. Actual start-after-removal-confirmation is rejected; pending cancellation preserves dispatched results. Exact native command counts detect replay.
- Lost native action response remains unknown; reconnect returns read-only. Controlled daemon probe identity drift refuses dispatch with unchanged command count. This is gate-projected drift, not a replaced Engine. Browser tests separately cover clearing stale selected rows on host changes.
- Initial lifecycle runs exposed the stale-read defect above; failed runs are not completion evidence. Initial Compose revocation WebKit click was not delivered; the helper now records trusted click delivery and retries only a click proven undelivered, never a dispatched mutation. Initial network assertion raced with read completion; bounded wait verifies the intended availability condition. Parallel post-fix attempts also caught an undelivered batch-enable click and a lifecycle assertion timing out while still pending; all native clicks now verify trusted delivery to the intended element, and the lifecycle wait covers its 30-second preflight plus command budget (50 seconds).
