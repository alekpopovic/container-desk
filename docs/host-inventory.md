# Saved host inventory

Hosts connects alias discovery, local metadata and explicit native connection state. Browse aliases reads only trusted SSH config candidates; selecting, saving, filtering or launching does not resolve/connect. A manually entered alias follows the same validation. Connect saved host resolves the saved original alias/config policy, opens its owned SSH transport and probes Docker. Disconnect and Retry are explicit. The error remains attached to the chosen host with actionable static diagnostics.

Each record receives a random backend HostId; display names may repeat. SSH alias/config identity must be unique in the saved inventory, while the same alias can refer to different explicit config files. IDs survive edits and restart. Labels are plain text; group choices include prod/staging/dev and custom existing groups. Favorites sort first and can be filtered. The sidebar summarizes groups; the full inventory is not truncated. Its polling component remains mounted across navigation, with one request at a time and stale-reply sequence guards, so health/idle loss remains visible in the workspace header.

Saving records the non-secret SSH selection reference, Docker binary/context/sudo options, display name, group, labels and favorite. Schema 3 migrates schema 1/2 while preserving IDs and exact previous bytes. Legacy records without per-host SSH selection resolve the former global reference when explicitly connected. Editing metadata preserves the saved default-versus-explicit SSH policy. New hosts start read-only. Existing read-only preferences are retained; management preferences never grant execution permission, and all current connections remain read-only. Management and terminal access require separate transient backend permissions and bound confirmations.

Transient snapshots carry an optional owning HostId, original selection, effective destination/jump summary, token/generation, stage diagnostics and Docker identity. A new owner, even for identical alias text, requires a new generation. The backend and renderer verify host/selection/Docker-option correspondence; results from a prior host cannot populate a different record. Editing a target/config/Docker mode disconnects the old attempt before storing the new target. Editing a favorite, name or label preserves the same active identity.

Remove from app is a local metadata action. It first stops that record's selected connection, then removes its record under the existing revision/atomic-storage rules. It never edits SSH config, keys or known_hosts, and never deletes a remote resource. A stale storage revision is rejected without retry. Inventory mutations and mode/connection transitions have a nonqueuing control gate. Every inventory command names its expected live/demo mode; a delayed demo request cannot write live settings after a mode change. Disconnect before changing workspace mode while a connection is retained.

Native demo uses the same coordinator with an explicit synthetic stage driver and separate in-memory metadata. Browser demo uses an explicit in-memory adapter and cannot fall back from native failures. Both provide direct and jump examples; neither performs SSH. Demo resource tables remain the separate synthetic read-workspace fixtures from 008, clearly labeled. Inventory connection previews do not create a resource SessionScope or change those tables. Live resource views dispatch through the verified native session; demo views remain synthetic.

Verification includes native direct/ProxyJump add/connect/disconnect/remove/reopen against the disposable SSH/CLI lab; schema migration and real files; native Tauri mock-runtime IPC for metadata; Rust identity/mode/concurrency checks; and browser demo plus live-bridge presentation tests in six sizes/themes. The lab's Docker API is synthetic, as documented in 016.
