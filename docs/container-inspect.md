# Container inspect details

After selecting a row in a fresh live inventory, ContainerDesk sends a typed full-ID inspect request through the existing read-only policy and native session. The registered `docker inspect --type container -- FULL_ID` command restricts the object type and returns a JSON array, as described in [Docker's inspect documentation](https://docs.docker.com/reference/cli/docker/inspect/). This increment uses the existing native OpenSSH transport and introduces no remote dependency.

Rust accepts exactly one matching object. An empty successful array or the bounded, exact known missing-container diagnostic produces `container_not_found`. Other failures remain errors; raw stderr and parser diagnostics never enter the UI. CLI not-found status handling follows the [Docker CLI 28.3.3 inspect implementation](https://github.com/docker/cli/blob/v28.3.3/cli/command/inspect/inspector.go). Current host/session scope is checked on dispatch and completion, with actual Docker binding checks around the command. Identity drift revokes the native session.

The adapter limits the whole operation to 30 seconds, stdout to 2 MiB and stderr to 16 KiB. It allows at most 1,024 environment entries, 1,024 labels, 128 mounts, 128 networks, 128 aliases per network and 128 normalized port bindings. Individual metadata strings are bounded to 4 KiB; environment/label values to 64 KiB. These are explicit application limits, not silent truncation. Reads share the four nonqueued backend permits and the connection owner's cancellation/reaping lifecycle.

The DTO projects lifecycle timestamps, exit code, restart policy/count, image ID, mount access, network addresses/aliases, port bindings and selected resource settings. Missing/null data remains unavailable; zero lifecycle timestamps become absent. Resource integers are decimal strings to preserve values beyond JavaScript's exact integer range. Health probe output, raw inspect JSON, command/entrypoint, log path and arbitrary unprojected fields are omitted.

All environment values and **all label values** are masked in Rust by default. Label keys cannot reliably establish whether a value is sensitive, so masking is deliberately conservative. Explicit `revealSensitive: true` applies only to that current-session request; there is no global reveal grant or persistence. Subsequent ordinary requests are masked again. Secret-bearing DTO entries have a Debug implementation that omits names and values, including after reveal.

The details view stores only its active selection in component memory. Hide clears values immediately; refresh begins with a masked request; switching route/container/session or refreshing the inventory unmounts the detail view. Full scope/ID keys and request serials discard late replies. A discarded UI snapshot request remains bounded by its deadline; closing the native connection cancels its process. React renders untrusted names and values as text.

The separate browser fixture tests interaction and stale-result behavior. Native Linux acceptance uses actual isolated Engine-created containers with synthetic environment/label values, direct and ProxyJump routes, actual release IPC and an external WebKit driver. It also scans app stdout/stderr and persisted app files for those values. Native rootless Engine operation, running healthchecks, macOS and packaging are not proven by the inspect shape fixtures.
