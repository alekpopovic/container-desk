## Environment and disposable topology

Local native app → direct SSH target, or local app → SSH bastion → private DNS alias `target`. Both servers run Alpine 3.22.5/OpenSSH 10.0p2 in separately owned, read-only containers on an internal bridge. No ports are published. The local Linux host reaches the owned bridge IP for the direct case; only the bastion resolves the private target alias. This tests actual TCP forwarding, not an emulated SSH client or network isolation against the host administrator.

`tests/lab/ssh_auth.py --engine` builds `containerdesk-ssh-lab:018` from the pinned Alpine digest in the Dockerfile. It selects an unused /28 without changing existing networks. Temporary client/server keys, dedicated known_hosts files and an isolated agent are generated under a private temporary directory. Trust entries come from the public keys of the owned servers, not an unauthenticated scan. A deliberately permissive source config tests that the application's strict overlay wins on both hops. No user key is copied or sent to a container.

A **real Docker Engine 28.3.3** runs inside the SSH target, separately from the host daemon. It uses private tmpfs data/exec directories, `vfs`, the target's own Unix socket and disabled bridge/iptables/ip6tables/IP-forwarding/masquerade. The container is not privileged and never receives the host Docker socket. The lab user belongs to the image's Docker group. The daemon is intentionally empty; running nested workloads is not claimed. The existing synthetic API fixtures remain solely for negative capability/format tests and are identified separately in output.

The orchestrator needs local Docker/Python/Cargo; the **application and compiled real-Engine test process run with `PATH=/nonexistent`**, using validated absolute `/usr/bin/ssh`. Neither needs client Docker or jq. The native app receives isolated `XDG_DATA_HOME`; no normal application preferences are edited. Snap-injected GTK/loader variables are removed only from its test process.

Client tools: OpenSSH 10.2p1 Ubuntu-2ubuntu3.6; Rust/Cargo 1.98.1; Node 24.21.0/npm 11.19.0; Tauri 2.12.0; GTK 3.24.52; WebKitGTK/WebKitWebDriver 2.52.6; external tauri-driver 2.0.4. Remote CLI/Engine: 28.3.3. Compose is absent in this lab and correctly remains optional.

## Combined boundary review

- `ssh/quoting.rs` supplies one POSIX encoder for the remote command; typed registry validation protects argument meaning. Local structured execution spawns validated native SSH directly with argv. Hostile quotes, shell substitutions, templates, leading options, NUL and output bounds have deterministic coverage.
- `ssh/auth.rs` overlays BatchMode, strict host verification, no trust updates, no password prompts and no agent forwarding. The lab covers unknown/changed keys at the target and bastion, encrypted keys with/without the isolated agent, and missing credentials. Original config/trust hashes remain unchanged. Trusted Match exec/ProxyCommand remain executable user configuration.
- `ssh/runner.rs`, `multiplex.rs` and `runtime.rs` retain process/resource ownership through cancellation and reaping, use bounded nonqueuing slots/output/deadlines, own private short control sockets and avoid implicit reconnect on dispatched mux channels. Native tests verify independent cancellation, user-master survival, socket removal and idle recovery. Slow remote subprocesses are confined to the disposable target; client cancellation is not a guarantee that an arbitrary remote program stops.
- `ssh/sessions.rs` invalidates generations before cleanup and ignores old completions. Inventory ownership also binds stable host ID and selected SSH/Docker options. UI cancel/reconnect plus deterministic stale-result tests cover both paths. There are still no authorized resource/mutation/terminal sessions from this diagnostic-only connection API.
- Diagnostics send static classifications and whitelisted capability fields; raw SSH stderr, credentials and environment values are absent from persistence and default IPC. Dedicated marker/hash tests cover invisible password/trust changes. The isolated Engine identity is compared independently and is never substituted with the synthetic API's identity.

Two older lab tests initially failed because they assumed the default socket had no Engine. They now explicitly select the existing stopped-daemon fixture, preserving that negative scenario whether the real Engine is enabled or not. The first WebDriver journey attempted an element before React mounted; the external harness now uses a bounded 5 s element wait. The subsequent complete run passed. These were harness assumptions, not bypassed app failures.

## Remaining limits and downstream work

macOS arm64/x86_64, native Wayland, Ubuntu 24.04 baseline and packaged installation remain unexecuted. This checkpoint needs only the available native OS; later platform gates still require real native evidence. The lab proves an empty real daemon, not nested container execution, streaming or mutations (030/038/046).

Existing documented limits remain: system-config relative Include semantics under the private SSH overlay; synchronous metadata on slow filesystems; conservative stale-socket recovery preserving ambiguous resources. The 019 resource dispatcher must avoid retaining the driver's connection mutex across its idle watcher, bind actual session/daemon identity and reject stale responses. None of those future operations are exposed by this checkpoint.
