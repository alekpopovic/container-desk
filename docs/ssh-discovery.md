# SSH configuration discovery

In Settings, **SSH host candidates** shows the absolute default user config path (`~/.ssh/config`, expanded using Tauri's home directory). A saved trusted config reference takes precedence when present. Enter a different absolute path to browse a custom trusted user configuration. Only **Browse host candidates** reads files; startup does not scan them, resolve aliases or connect. Paths remain user references, including symlinks; candidate source paths are canonicalized to detect cycles.

Choose a listed alias or enter a manual alias. Both selection paths call the same Rust validator and return an in-memory draft containing the original alias and config path. Selection does not save a host, resolve effective configuration or connect yet; those are later increments. Supported aliases are 1–256 ASCII letters/digits/dot/underscore/dash and must start with a letter or digit. Use a simple config alias for IPv6 literals, user@host or other unsupported names.

The convenience parser reads literal Host tokens, multiple aliases, case-insensitive directives, optional `=`, double-quoted values and comments. It follows literal Include paths and bounded `*`/`?` globs in lexical order. `~/` refers to the local home directory; relative user includes are based on `~/.ssh`, even when the including file is elsewhere. It does not enumerate wildcard/negated Host tokens. OpenSSH remains authoritative for actual matching and precedence. These rules follow the [OpenSSH configuration reference](https://man.openbsd.org/ssh_config#Include).

Discovery deliberately skips includes under Host conditions other than a single `Host *`, and all Match blocks. It never evaluates Match exec, ProxyCommand, environment variables, percent tokens, other-user tilde expansion or bracket/brace glob expressions. Unsupported/conditional cases receive typed notes and retain the manual-alias path. A later Host line starts a new condition; include file conditions carry back into the surrounding stream. Candidate presence is not proof of a resolvable/reachable destination.

Bounds: 1 MiB per file, 4 MiB total, 128 file attempts, 16 nesting levels, 4,096 glob directory entries, 16 KiB per line, 1,000 distinct aliases and 128 deduplicated notes. Regular files only; nonblocking/no-follow open after canonicalization rejects special files and replacement symlinks. No file writes, process API, DNS lookup, private-key inspection or raw directive contents in IPC. Missing files, cycles, unsupported syntax and reached limits remain visible. Local filesystem calls run on a blocking worker with an owned single-flight permit; abandoning the IPC future cannot release the permit while that worker still runs. Slow network-mounted filesystems do not have a guaranteed wall-clock deadline, so use local config files.

Demo mode rejects discovery and alias selection in Rust. Mode switching is excluded during discovery using the same bounded native-operation slot as dependency diagnostics. Frontend paths/aliases are rendered as text, and response shapes are validated. Browser tests use an explicit IPC fixture and are not native file-access evidence.
