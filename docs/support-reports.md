# Support reports and local troubleshooting data

Settings → Support report and local history prepares an app-controlled JSON preview. It does not run a new SSH command. The backend reads the current connection snapshot and bounded local activity, then builds a new object from an explicit field allowlist. It never serializes those source objects wholesale or tries to remove secrets from raw text afterward.

The report contains the build version, platform/architecture, native OpenSSH connection policy and current transport mode, jump presence, connection state, staged error codes, up to three connection durations, and the latest 20 activity summaries. Timings are rounded down to 100 ms and capped at 30 seconds per connection stage or one hour per activity. There are no wall-clock timestamps. Unavailable settings, connection or activity sources contribute only typed source/error codes; the report remains available without guessing missing configuration. Host identities become report-local `host-N` pseudonyms; selected executable/config references become fixed path labels. The mapping is not exported. A report may still reveal operational facts through versions, counts and outcomes, so review it before sharing.

No free-form user text is accepted into this report. It excludes hostnames, aliases, addresses, usernames, saved labels, actual paths, daemon/container/session/intent IDs, executable version output, exception messages, SSH config/key contents, credentials, environment values, logs, terminal text and full inspect data. There is no attachment field that can silently append these. If you add your own description outside the application, review that text separately.

Preparing a report replaces the previous in-memory preview. At most one preview of at most 64 KiB is retained. Its random identifier is valid for five minutes; expiry is checked before and after the native save dialog. Expired data is dropped on access, replacement, explicit clearing or process exit, rather than persisted to a diagnostic log. The frontend sends only the reviewed identifier to Save, never report content or a filesystem path. The backend saves those exact frozen bytes through the user's native file chooser, with a private 0600 temporary file, sync and atomic replacement. Cancel writes nothing. Saving consumes the preview. No export is retried automatically or uploaded anywhere.

## Local retention and clearing

The existing local activity store retains at most 200 records and 512 KiB, dropping the oldest eligible record while preserving currently owned operations. It is a bounded history, not a tamper-proof audit trail or replay queue. There is no age-based expiry: eligible records remain until capacity replaces them or the user clears them. The application does not add a persistent diagnostic-text log in this increment.

**Clear local troubleshooting data** asks for confirmation, then atomically replaces the app-owned activity history with an empty history and invalidates the prepared report. The backend refuses while an activity operation is active or a native save dialog/write holds the export slot. Failure to write leaves the in-memory history intact and returns the existing storage error. New operations can create new records afterward.

The clearing scope is local troubleshooting history and prepared diagnostics. Saved host references/preferences stay under their existing settings controls; removing a host remains the separate Remove from app action. Clearing never traverses the home directory, deletes SSH config, keys or known_hosts, or removes user-chosen exported files. It is logical deletion of the application's history, not a secure disk wipe. Existing connection status can still appear in a subsequently prepared report because it describes the current connection.

Verification covers typed error categories, actual private filesystem writes and SSH-file preservation, preview replacement/expiry, active-operation/save exclusion, browser text rendering, and a real native GTK Save/Cancel journey. Platform results are recorded in the prompt 043 evidence.
